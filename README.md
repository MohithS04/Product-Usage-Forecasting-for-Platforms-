using historical behavioural data, SQL analytical queries, and a Python
time-series model — targeting **≥ 95 % forecast accuracy** and automated
monthly variance reporting.

## Project Overview

This project was built to help GitLab Platform Engineering teams answer three
recurring questions every month:

1. **What will platform load look like in the next 3 months?**
2. **How accurate were last month's forecasts?**
3. **Which sections need infrastructure changes, and when?**

The pipeline integrates 24+ months of historical platform usage data (active
users, CPU, memory, API calls, pipeline runs) to project future load and
generate plain-language recommendations for product managers.


```bash

```

## Components

### SQL Layer

The `sql/` directory contains four PostgreSQL scripts that implement the full
SQL-side forecasting workflow:

| Script | Purpose |
|--------|---------|
| `schema.sql` | Creates tables: `platform_usage_metrics`, `monthly_usage_summary`, `usage_forecasts`, `forecast_variance`, `scaling_recommendations` |
| `seed_sections.sql` | Inserts the 8 GitLab platform sections |
| `forecasting_queries.sql` | Moving averages, MoM growth rates, seasonal indices, least-squares regression, 3-month-ahead forecast |
| `variance_analysis.sql` | Upserts `forecast_variance`, rolling accuracy trends, miss analysis |
| `infrastructure_scaling.sql` | Generates `scaling_recommendations` with plain-language PM summaries |

**Load order**: `schema.sql` → `seed_sections.sql` → (load data) →
`forecasting_queries.sql` → `variance_analysis.sql` → `infrastructure_scaling.sql`

### Data Generation

`data/generate_data.py` produces a realistic synthetic dataset with:

- **8 platform sections** each with their own baseline, growth rate, and seasonal pattern
- **Daily granularity** with business-day / weekend differentiation
- **Gaussian noise** on all metrics for realism
- Configurable via `--months` and `--seed` flags

```bash
python data/generate_data.py --months 36 --output data/platform_usage_36m.csv
```

### Forecasting Model

`forecasting/model.py` implements `UsageForecaster`:

```python
from forecasting.model import UsageForecaster, load_monthly_data

monthly = load_monthly_data("data/platform_usage.csv")

forecaster = UsageForecaster()
forecaster.fit(monthly)

# 3-month-ahead forecast with 95% prediction intervals
forecast_df = forecaster.predict(horizon=3, confidence=0.95)

# Evaluate against known actuals
eval_df = forecaster.evaluate(test_monthly, forecast_df)
print(eval_df[["section_name", "metric", "accuracy_score"]].to_string())

# Plain-language scaling recommendations
recs = forecaster.scaling_recommendations(forecast_df)
print(recs["pm_summary"].tolist())
```

**Algorithm**: Exponentially-weighted linear trend + month-of-year seasonal
indices. Recent months receive ~5× higher weight than the oldest observations,
improving responsiveness to usage shifts.

### PM Report Generator

`forecasting/report_generator.py` translates analytical findings into a
Markdown report and Tableau-ready CSV files:

```bash
python forecasting/report_generator.py --output reports/
```

The generated `PM_Report_YYYY-MM.md` contains:

- Executive summary with plain-English trend statements
- Per-section forecast table (users, CPU %, memory, scaling action)
- Forecast accuracy scorecard
- Infrastructure scaling priority table
- Glossary of technical terms

### Tableau Dashboards

See [`tableau/dashboard_guide.md`](tableau/dashboard_guide.md) for step-by-step
instructions to build four dashboards:

1. **Platform Load Overview** – historical trends, section comparison
2. **3-Month Forecast** – predicted load with confidence intervals
3. **Forecast Accuracy** – model accuracy vs 95 % target
4. **Scaling Recommendations** – color-coded urgency + PM summaries

## Testing

```bash
python -m pytest tests/ -v
```

The test suite covers:

- Data generation: CPU bounds, reproducibility, all sections present
- Model helpers: `_add_months`, `_z_score`
- `UsageForecaster`: fit, predict shape, CI ordering, CPU cap, horizon control
- **95% accuracy integration test** (train on 21 months, forecast 3, assert ≥ 95%)
- Variance analysis: `compute_variance`, `monthly_summary`, pipeline end-to-end
- `load_monthly_data`: column schema, format, no nulls

## Accuracy

The model is validated against a 3-month held-out period every time the test
suite runs. The integration test (`TestAccuracyTarget::test_overall_accuracy_meets_95_pct_target`)
asserts:

```
Global accuracy ≥ 95.0%
```

This matches the project requirement of *"95% accuracy rate compared to actual
results"* and is enforced on every `pytest` run.
